Author: jayis1

## Executed checks

- Clean target build: `make -C slip-window/firmware clean all test` with ARM GNU GCC 14.2.1. Linked for Cortex-M4 / STM32F401RE without an SDK; 2,280 bytes text, zero initialized data, 276 bytes static BSS. This excludes stack usage and does not constitute a measured runtime memory high-water mark.
- Production firmware count: 507 nonblank, noncomment C lines plus 99 header lines; tests and build products excluded.
- Engine and encoder host tests: passed with address and undefined-behavior sanitizers. Exercises normal casting, incomplete tips, drain interruptions, exact segment accounting, early opening, contradictory stops, repeated marking, sampling discontinuity, chatter, timestamp wrap, timeout boundaries, counter exhaustion, qualification/arming boundaries, CRC reference vector, and insufficient output buffer.
- Seven Python protocol/model tests: passed using actual C-encoder output. Includes CRC damage, framing recovery, every-boundary fragmentation, modular wrap, cumulative-counter rollback, stale data, provenance, and exclusive CSV creation.
- Real Tk event loop under Xvfb with a Linux PTY: passed three-screen navigation, live serial fixture ingestion, batched history rendering, stale indication, reconnect clearing, disconnect preservation, simulated unplug, and offline replay. A serial-attribute restoration error found during unplug testing was fixed and this workflow rerun successfully.
- Python compilation: application, tools, and tests compile with Python 3.13.5. No third-party Python packages are required for the application; system KiCad Python bindings are needed only for hardware generation/checking.
- KiCad 9.0.2: schematic ERC zero violations; PCB DRC zero violations; zero unconnected items. Fresh XML schematic netlist compared against actual PCB pads and manifest: 14 components, 30 pins, 10 nets, with matching values and full footprint identities.
- Exported schematic SVG rendered to PNG and visually inspected: four separated resistor/contact channels, readable references and labels, no apparent label collisions. Images are inspection outputs outside the repository, not additional deliverables.
- README count: 3,223 whitespace-delimited words. Release checker verifies attribution in every tracked/unignored device file, minimum content thresholds, required board-map markers, file sizes, and absence of private-key headers.
- Existing-device inventory: 84 top-level README titles inspected; casting/mold terminology searched; closest conceptual neighbors documented. This is repository deduplication, not a worldwide novelty determination.
- An independent read-only code review found no blocking bug, recommended reset/counter checks and additional boundary tests. Counter rollback detection and the recommended timing/fragmentation tests were added and passed.

## Evidence boundaries

No board was fabricated, assembled, electrically measured, programmed, or attached to a real casting cradle during this run. The Nucleo peripheral mapping was checked against the existing local UM1724 manual; fresh retrieval from the manufacturer failed. The supplied RM0368 link identifies the register-map reference, not a claim that a new copy was downloaded. The reed family description was checked against manufacturer search results; stock, chosen sensitivity, mounting distance, and low-current switching reliability need procurement/bench qualification.

Tests cover synthetic input, actual compilation/linking, CAD rule checks, net consistency, and desktop behavior. They do not establish sensor reliability, absolute clock accuracy, EMC/ESD performance, enclosure safety, clay quality, or readiness to demold. Reset inference lacks a persistent boot identifier and is explicitly heuristic. The project is a build-tested engineering prototype with a routed passive carrier, not a production-certified product.

## Reproduce

Run the commands in README's build section from the repository root. The fixture is regenerated by `make test`; do not interpret it as physical measurements. `tools/generate_hardware.py` regenerates native KiCad artifacts with the system Python interpreter. Re-run hardware checks after regeneration or any wiring/footprint edit. Build products, Python caches, and local KiCad preference files are ignored and must not be committed.
