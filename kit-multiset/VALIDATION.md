# Kit Multiset validation record

Author: jayis1

This record covers software and design-file verification in standalone-owner mode. Advisory peer reports informed the gates; no independent collective sign-off or physical hardware test is claimed.

## Reproducible command

From the repository root:

    python3 kit-multiset/tools/check_quality.py

The gate performs a clean Cortex-M4 target build, three sanitizer-enabled C test executables, Python model/transport tests, an actual Tk event loop under Xvfb, KiCad ERC/DRC, netlist-to-pad comparisons, attribution checks and whitespace checks. Build outputs, Python caches and KiCad local preferences are ignored, not published.

## Observed results

- arm-none-eabi-gcc 14.2.1 linked the actual STM32F401 target successfully with warnings as errors. ELF section sizes: 2392 bytes text, zero initialized data and 788 bytes BSS. The stack additionally holds the engine and snapshot buffer. The binary was generated by objcopy.
- Production firmware comprises 652 C/header lines, including 581 nonblank lines after C comments are removed. Tests are excluded from both figures.
- README has 3298 whitespace-delimited words.
- Engine tests passed all twelve distinct permutations of A,A,B,C and 1093 independently counted words over A/B/C through length six. Additional checks cover held paddles, rejected short pulses, unrelated-channel chatter, startup with a paddle asserted, gap abandonment, repeated batches, raw tray attribution loss, timeout, exact deadline precedence, counter exhaustion and timestamp wrap.
- Production clock and UART tests passed their register-mask, bounded-wait, transmitter capacity, busy-rejection, timeout and wrap cases under AddressSanitizer and UndefinedBehaviorSanitizer.
- Seven Python unittest methods passed. Tests include CRC rejection, truncated-frame recovery, partial replay tails, invalid state/accounting, contradictory duplicate frames, stale reception, serial attribute restoration, actual PTY hangup, FIFO replay rejection and exclusive CSV creation.
- A fixture produced by the actual C engine and encoder was consumed by the Python replay model and the actual Tk GUI. Both matching and mismatching outcomes appeared, with two history rows. This fixture is synthetic.
- GUI testing used a real Tk event loop and POSIX pseudo-terminal: connection, advancing telemetry, LIVE status, duplicate-open refusal, export, hangup, invalid non-TTY path and retained evidence were exercised. No physical USB device was attached.
- KiCad 9.0.2 ERC reported zero violations. DRC reported zero violations and zero unconnected items. A freshly exported schematic netlist matched the PCB and manifest across 14 components, 30 pins and 10 nets, including component values and full footprint identifiers.
- An SVG schematic export was rendered and visually inspected. Supply/input connector labels, the four resistor/contact rows and the jayis1 title attribution were legible without observed label collisions.
- Every first-party deliverable contains jayis1 attribution in valid source comments or metadata. The root index receives only the new device entry. No changes are made to other device folders or other repositories.

## Scope and limitations

The custom board is passive; MCU power, reset, programming, decoupling and the UART/USB bridge reside on an external NUCLEO-F401RE. ERC and DRC do not validate that purchased board, external harnesses or switch mechanics. No fabricated board, on-device execution, accuracy measurement, ESD test, EMC test or user trial is represented by these results.

The manufacturer's primary PDF download endpoints failed during this run (HTTP/2 failure and subsequent bounded timeout). Connector assignments were cross-checked against indexed UM1724 table content from a university-hosted mirror; the existing target platform's register sources and executable register tests were reviewed. This is not a claim that a fresh complete datasheet audit was performed.

Commercial kitting and pick-to-light products are explicitly acknowledged in the README. The contribution is differentiated from the inspected repository devices, not demonstrated globally unprecedented. Stroke declarations do not establish actual item quantity or identity. The application checks necessary evidence invariants, not a complete proof that every sparse snapshot history is physically realizable. Some resets remain indistinguishable without persistent boot identity.

Physical procurement, fabrication, assembly, switch placement, current measurement, timing verification and supervised workflow evaluation remain future commissioning work. Use only dry, inert, non-safety-critical teaching materials.
