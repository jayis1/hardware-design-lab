# Tooth Census validation record

Author: jayis1

## Scope

This record distinguishes executable-source verification from unperformed physical testing. The design is an unbuilt prototype. No board was fabricated, MCU flashed, contact fixture assembled or gear measured. Accepted synthetic captures are not physical measurement data. The execution mode was standalone owner with advisory reports, not a completed independent collective design review.

## Executed checks

- GNU Arm Embedded GCC 14.2.1: freestanding STM32F401 Cortex-M4 target compilation and linking with warnings as errors. The initial target image reported 2776 bytes text, zero initialized data and 788 bytes BSS; the linker reserves at least 4096 bytes of stack. The verification command rebuilds and prints current sizes.
- Host GCC: production engine and CRC writer tested with AddressSanitizer and UndefinedBehaviorSanitizer. Both direction polarities and every synthetic tooth count from zero through ninety-six passed. All sixteen ordered quadrature transitions are checked against a separate ring-position oracle. Tests also cover reference learning, mismatches, count ranges, reversals, illegal jumps, insufficient edges, boundary overlap, a raw glitch on the cut, timeout immediately before and exactly at its rejecting boundary, acquisition loss, halted evidence, counter limit, clock wrap, startup-high index, chatter, small output buffers and the standard CRC vector.
- Shared clock and input configuration tests passed, including bounded clock-failure paths. Shared production UART tests passed for buffer bounds, busy refusal, nonblocking draining, timer wrap and timeout recovery.
- A recording generated by the real production C encoder contains three accepted synthetic captures with counts twelve, eleven and ten, followed by a rejected reversal. The application reports three accepted captures, one rejection, two mismatches, reference twelve, range ten to twelve and total thirty-three.
- Ten Python unittest cases passed under Python 3.13.5 and Xvfb/Tk. Coverage includes production-encoder replay, CRC errors and framing recovery, impossible CRC-correct records, reference/result immutability, duplicate timestamp behavior, delayed reception, private exclusive-create CSV, FIFO/empty replay rejection, POSIX serial attribute restoration, real Tk screen population, PTY reception and hangup, duplicate connection refusal, reconnect display clearing and preservation of prior replay after a failed serial open.
- KiCad 9.0.2 native schematic ERC: zero violations. Native PCB DRC: zero violations and zero unconnected items. Fresh XML schematic-netlist comparison agrees with actual PCB values, footprint identifiers and every reference/pin/net: fourteen components, thirty pins, ten nets. The schematic was exported to SVG, rendered to PNG with rsvg-convert and visually inspected for channel layout, connector labeling and readable title/author information.
- README word count and production C/header counts are enforced by tools/verify.py. Production C excludes comments, blank lines and test code. Every included text artifact carries jayis1 attribution in format-valid comments, metadata or native title fields. Build products and KiCad local preferences are ignored.

## Reproduction

From this device directory:

    python3 tools/verify.py

That command cleans and target-builds firmware, runs sanitized host tests, generates the synthetic recording, runs the application tests under Xvfb, compiles Python sources, executes native CAD checks, counts documentation and production source, and audits file attribution. Generation of CAD is separate and requires the installed KiCad Python module:

    /usr/bin/python3 tools/generate_hardware.py

The common acquisition, startup, UART and CAD infrastructure comes from jayis1's Sector Soak at e8a0f67. The import script refuses existing destinations and is provenance/reproduction documentation, not a command to run over an existing design.

## Research and unresolved physical checks

The Bourns PEC11R PDF was retrieved and read, including contact quadrature, bounce conditions, assembly warning and recommended filtering. Fresh retrieval of ST UM1724 failed via HTTP/2 and timed out via HTTP/1.1; the pin map and register infrastructure were reviewed against the existing repository platform, not falsely represented as a new successful manual download. Confirm the actual MB1136 board revision before wiring.

The 0.300 mA contact current, approximately 0.300 V closed input and 1.200 mA all-closed carrier demand are nominal calculations. Minimum contact-current reliability, input thresholds under resistance variation, physical bounce, magnetic hysteresis, mechanical phase margins, coupling slip, follower loading, maximum speed, long-term timing drift, ESD and EMC remain unverified. No isolation or protective control function is provided. Passive-only ERC does not validate external power or sensors.

The GUI tests use Linux pseudoterminals and synthetic telemetry, not USB hardware. Sparse protocol checks constrain possible histories but cannot reconstruct unreported individual events or authenticate a serial source. An unnoticed whole-cycle encoder dropout, consistently wrong follower count, bad first reference or some MCU resets can escape detection. These are disclosed limitations, not waived safety certification criteria.
