## Browser exercise

The real browser loaded the three-screen application from a localhost HTTP server. A trace generated by `tests/fixture.c` through the production C engine and encoder produced 53 snapshots. Replay ended with one accepted cycle and one ORDER rejection. The UI explicitly displayed SYNTHETIC REPLAY and NOT LIVE, changed the station prefix to Crease, and generated a CSV blob containing the attribution, header, and all 53 records. Navigation between Live, History, and Connection screens was exercised.

A mocked Web Serial transport fed a valid C-encoded frame through the actual app read loop. The display became fresh, became stale after approximately two seconds without a further frame, and became disconnected on user cancellation. This checks application behavior, not a physical serial interface. The capture/export test inspected the generated Blob before native file download, so OS-level download completion is not claimed.

Independent read-only review identified an asynchronous replay/connect race and a delayed-open cancellation bug. Both were reproduced as failing tests before correction. Mutual exclusion across connection/replay and a generation token now prevent pending work from reviving a canceled session or labeling synthetic data as live. Both regression tests pass.

## Reproduction of synthetic trace

From the repository root:

```sh
gcc -std=c11 -Wall -Wextra -Werror -Ifold-trace/firmware \
  fold-trace/tests/fixture.c fold-trace/firmware/engine.c \
  fold-trace/firmware/wire.c -o "$TMPDIR/fold-fixture"
"$TMPDIR/fold-fixture" > "$TMPDIR/fold-trace-synthetic.log"
```

Choose that log from the replay input. Set TMPDIR to a writable scratch directory if the environment does not already define it. The trace is generated test data, not measured performance. Do not commit generated binaries or scratch logs.

## Remaining physical work

No PCB was fabricated. No target was flashed. There is no measured switch timing, contact-force qualification, ESD/EMC result, verified USB enumeration on a Nucleo, or real-carton acceptance rate. Power consumption beyond the passive resistor calculation is a design budget. The board is not galvanically isolated and must only connect to disconnected voltage-free switches. Firmware counters are volatile. A CRC is not authentication, and an inferred uptime reset is not a unique boot identity.

These results establish reproducible software builds and a connected, rule-checked passive carrier suitable for supervised prototyping. They do not establish a certified product, machine safety function, or commercial novelty.
