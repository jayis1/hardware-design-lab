The Engine and frame buffer are stack allocations, so BSS is not a total RAM-use claim. Linker reserves a 4096-byte minimum stack margin.
- `arm-none-eabi-readelf -h firmware/build/peel-front.elf`: ELF32, little-endian ARM EABI executable, entry address 0x080005a3 (Thumb entry).
- Host C tests use `-Wall -Wextra -Werror -fsanitize=undefined,address`. Three executables passed: measurement engine, clock/configuration masks and production UART driver.
- Engine tests cover a complete asymmetric peel, timestamps and derived fixture values, premature downstream events, reclosure, missed acquisition, new-baseline recovery, thirty-second timeout, exact-deadline precedence, simultaneous openings, rejected glitches, independent qualification, uint32 clock wrap, identifier/counter exhaustion, bounded encoding, and all distinct four-input opening permutations.
- Clock tests use simulated registers and cover bounded HSI/switch/PLL failure paths, input masks and forbidden receive enable. They do not prove oscillator startup on silicon.
- UART tests exercise the production driver with simulated registers: invalid lengths, busy rejection, nonblocking progress, timeout at the exact boundary, unsigned wrap and subsequent recovery.
- `xvfb-run -a python3 tests/test_app.py`: six tests passed under Python 3.13.5. These include real Tk event-loop operation and page selection, a Linux pseudo-terminal feeding a production-C-encoded fixture, retained trial display, unplug detection, repeated connection refusal, termios restoration, CRC-valid impossible snapshots, truncated-frame resynchronization, replay EOF rejection, FIFO rejection, exclusive private export, reset suspicion, prolonged reception pauses and gradual backlog.
- `python3 app/peel.py --check firmware/build/fixture.txt`: passed, one synthetic retained trial. This is an interoperability test, not a physical capture.
- `/usr/bin/python3 tools/generate_hardware.py`: generated fourteen components and ten nets.
- `/usr/bin/python3 tools/check_hardware.py`: KiCad 9.0.2 ERC zero violations; DRC zero violations and zero unconnected items. Fresh exported schematic netlist, component values, footprint identifiers and all thirty reference/pin/net assignments match the PCB and manifest.

## Not verified

No fabrication, MCU programming, live USB hardware capture, electrical power measurement, oscillator calibration, watchdog reset on hardware, mechanical force measurement, enclosure qualification, specimen comparison or environmental/ESD test was performed. No global novelty or patent clearance is asserted. Direct manufacturer UM1724 PDF retrieval timed out; the documented inherited connector map must be confirmed against the actual board revision before physical assembly. KiCad footprints require ordinary fabrication review and upstream license compliance.

The carrier is a conventional passive interface. The design's distinguishing and most uncertain element is the mechanically latched four-point sensing geometry. Its follower displacement and release force targets are unverified. Until video correlation establishes that the flags observe rather than substantially alter lift, the output is a record of switch openings, not validated peel-front metrology.

## Reproduction

Run all commands from the device folder. Build outputs and KiCad local preferences are ignored. Firmware fixture data is regenerated by the host C test. The app uses only the Python standard library plus the distribution's Tk support. Replay expects PF1 wire-format text, not exported analysis CSV. Use separate files for independent powered sessions; receive-only restart detection is necessarily incomplete without a persistent boot identity.
